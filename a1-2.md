# Activity 1 – Step 2: A specific prompt with context

**Chatbot / model:** Gemini 3.1 Pro

## Prompt

```text
Act as a professional software tester and suggest test ideas for the feature delimited by three hashes. All test ideas should be focused on discovering risks that impact the quality characteristics: Functionality, Data Integrity and Security
###
* As a paralegal, in order to store and share legal documents, I want to be able to securely upload documents.
* Acceptance criteria:
  - Upload should support the following common file formats: PDF, DOCX, TXT
  - The maximum file size should be 20MB
  - When a document is uploaded it should give a progress update to the user
  - Once uploaded, the document must initially be only accessible to the person who has uploaded it
  - A report of the upload and whether it was successful or not will be stored in the auditing feature
###
```

## Response

Here are targeted test ideas for the document upload feature, categorized by your requested quality characteristics.

### Functionality

* **Boundary Value Analysis on File Size:** Upload files exactly at 20.00MB (should pass) and 20.01MB (should fail gracefully with an error message).
* **Format Validation:** Upload supported formats (PDF, DOCX, TXT) and verify rejection of unsupported formats (e.g., XLSX, PNG, RTF) with appropriate user feedback.
* **Progress Indicator State Changes:** Verify the progress bar updates in real-time, pauses or errors out if the network connection drops mid-upload, and definitively hits 100% upon completion.
* **Audit Logging Triggers:** Verify the auditing system records a "success" entry for completed uploads, and a "failure" entry (with the specific reason, like "size limit exceeded") for blocked uploads.
* **Concurrent Uploads:** If the UI allows it, attempt uploading multiple files simultaneously to see if the progress tracker and auditing system handle parallel processing correctly.

### Data Integrity

* **File Hash Verification:** Download the document immediately after upload and compare its MD5/SHA-256 hash against the original file to ensure zero data corruption or unwanted compression during transit/storage.
* **Filename Edge Cases:** Upload files with extreme filenames (e.g., 255+ characters, SQL injection payloads, special characters like `&, %, $`, and non-ASCII/Unicode characters) to ensure the database stores them without truncation or escaping errors.
* **Zero-Byte Files:** Upload an empty (0-byte) PDF or TXT file to see if the system handles it correctly or crashes during processing.
* **Audit Log Accuracy:** Verify the audit trail captures the exact metadata perfectly (correct timestamp, uploader ID, exact original filename, and precise file size).

### Security

* **Horizontal Privilege Escalation (Access Control):** Upload a document as Paralegal A, extract the file's direct URL/ID, log in as Paralegal B, and attempt to access it. The system must deny access.
* **Unauthenticated Access:** Attempt to access the newly uploaded document's direct link via an unauthenticated session (e.g., an incognito window).
* **File Extension Spoofing:** Rename an executable file (`script.exe`) to a valid format (`script.pdf`) and attempt to upload it. The system should perform deep MIME-type or magic-number validation, not just rely on the `.pdf` extension.
* **Malicious Payloads:** Upload validly formatted DOCX or PDF files that contain embedded malicious macros or JavaScript to verify if backend antivirus/scanning is active.
* **Path Traversal:** Intercept the HTTP upload request and manipulate the filename parameter to include directory traversal sequences (e.g., `../../../system32/malicious.txt`) to ensure files are stored securely and not overwriting server systems.
