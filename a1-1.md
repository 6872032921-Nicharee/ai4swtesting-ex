# Activity 1 – Step 1: A vague prompt

**Chatbot / model:** Gemini 3.1 Pro

## Prompt

```text
Create tests for a file upload feature
```

## Response

## Functional Testing

* **Valid Formats:** Upload files matching every supported format (e.g., `.jpg`, `.pdf`, `.csv`) and verify they are successfully saved and rendered/downloadable.
* **Invalid Formats:** Attempt to upload unsupported formats (e.g., `.exe`, `.bat`, `.sh`) and verify they are rejected.
* **Boundary Sizes:**
* Upload a file exactly at the maximum allowed size limit.
* Upload a file exceeding the limit by 1 byte (must trigger an error).
* Upload a 0-byte (empty) file.


* **Missing Selection:** Submit the form without selecting a file.
* **File Naming Edge Cases:** Upload files with special characters (`!@#$%^&*`), leading/trailing spaces, foreign characters, and extremely long names (e.g., 255+ characters).
* **Duplicate Names:** Upload a file with the exact same name as an existing file to verify the system's conflict resolution (overwrite, append a number, or reject).
* **Batch Uploads:** If supported, upload multiple files simultaneously, exceeding the maximum allowed batch count.

## Security Testing

* **MIME Type Spoofing:** Rename a malicious script (e.g., `script.php`) to a permitted extension (`script.jpg`) to ensure the backend validates the actual file signature/magic bytes, not just the name.
* **Double Extensions:** Upload a file named `malicious.php.jpg` to check for parser bypass vulnerabilities.
* **Path Traversal:** Intercept the upload request and modify the filename to include directory traversal characters (e.g., `../../../etc/passwd` or `..\..\windows\system32`) to ensure the server sanitizes paths.
* **Malware Scans:** Upload the standard EICAR test file (a harmless string that antivirus software flags) to confirm malware detection is active.
* **XML External Entity (XXE):** If accepting `.xml` or `.svg` files, inject malicious XML payloads to test for parsing vulnerabilities.

## UI and Usability Testing

* **Drag and Drop:** Verify files can be successfully dragged from the OS and dropped directly into the designated upload zone.
* **Progress Indicators:** Upload a large file and confirm the progress bar updates accurately and smoothly.
* **Cancellation:** Abort an ongoing upload midway; verify the network request is killed and no partial file artifact is left on the server.
* **Error Messaging:** Ensure errors are human-readable (e.g., "File too large") and do not leak stack traces or server paths.

## Network & Performance Testing

* **Network Throttling:** Throttle the connection to 3G speeds using browser dev tools and verify the upload completes without timing out the application.
* **Interrupted Connections:** Disconnect the network midway through an upload, then reconnect to see if it resumes or fails gracefully.
* **Concurrency (Load Testing):** Simulate multiple users uploading maximum-sized files simultaneously to monitor server memory, CPU usage, and storage allocation limits.
